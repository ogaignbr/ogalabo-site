ChatGPT課金者の次の一歩

ChatGPTを使う人から、AIエージェントと共創する人へ。

これからの仕事は、AIに質問するだけでは足りません。背景を渡し、作業を任せ、結果を見て、また直す。Codexはその練習を、ChatGPTの延長線上で始めやすい入口です。

KEY MESSAGE

この資料で伝える結論

1

Codexは「会話相手」ではなく「作業する仲間」。 ファイルを読み、変更し、検証まで進められる。

2

初心者ほど音声入力が大事。 短い手打ち指示では背景が抜け、AIの判断がズレやすい。

3

中途半端なAI活用では弱い。 仕事の前提をAIと共創する形へ組み替える人が強くなる。

MINDSET

「ちょっとAIが使える」では、もう足りない。

AI時代に価値が出るのは、AIに答えを聞く人ではなく、AIに文脈を渡して一緒に成果物を作れる人です。

PHASE 1

質問する

ChatGPTに聞いて、文章やアイデアを出してもらう段階。入口としては正しいが、ここで止まると差はつかない。

PHASE 2

任せる

Codexにフォルダ・目的・制約を渡し、調査、修正、検証を進めてもらう段階。ここからAIエージェント活用が始まる。

PHASE 3

共創する

AIの提案を見て、追加の背景を音声で足し、何度も改善する段階。仕事の進め方そのものが変わる。

BASIC DIFFERENCE

ChatGPT、Codex、Claude Code、AIエージェントの違い

種類 初心者向けの理解 得意なこと 最初の使い方
ChatGPT 相談相手・文章作成・壁打ち 考えを整理する、説明する、文章を作る 悩みや目的を話して、方向性を作る
Codex ファイルを見て、作業もするAIエージェント HTML作成、コード修正、資料生成、検証 フォルダを開き、目的を音声で渡す
Claude Code 開発者向けに強いコーディングエージェント 大きなコード理解、実装、並列作業 中級以降、開発量が増えたら検討
AIエージェント 目的に向かって、調べて、動いて、直すAI 人の代わりに作業工程を進める 小さな作業を1つ任せる

WHY CODEX FIRST

なぜ最初はCodexなのか。

理由はシンプルです。ChatGPTをすでに課金している人が、追加の心理的ハードルを低くAIエージェントへ移れるからです。

ChatGPTアカウントで始めやすい

OpenAI公式ヘルプでは、CodexはFree、Go、Plus、Pro、Business、Edu、EnterpriseなどのChatGPTプランに含まれると案内されています。利用上限はプランで変わります。

作業ファイルとつながる

CodexはコードやHTMLだけでなく、ドキュメント、スプレッドシート、プレゼンなどの非コード成果物も扱える入口になります。

Windowsでも使える

Codex appはWindowsでもPowerShellとWindows sandboxに対応しており、Windows利用者でも始めやすい設計です。

Claude Codeは次の段階

Claude Codeは強力ですが、最初から複数課金や開発者向け操作に寄せるより、まずCodexでAIエージェントの感覚を掴む方が続きやすいです。

VOICE FIRST

音声入力がないと、AIはズレやすい。

AIエージェントは、背景を知らないまま作業すると勝手に判断します。だから初心者ほど、口で長く説明するのが強いです。

短い手打ち指示

「このページをいい感じにして」だけだと、AIは目的、読者、制約、使う場面を推測します。推測が増えるほど、成果物はズレます。

背景が抜ける → AIが推測する → 直しが増える

音声で渡す指示

「誰に向けた資料で、何を理解してほしくて、どこは強く言いたくて、デザインは後で見る」まで話すと、AIの判断が安定します。

文脈が増える → 判断が揃う → 修正が速い

Codex appでは、composer表示中に Ctrl + M を押しながら話す。

まずは録音のように話して、文字起こしされた内容を少し直して送る。これだけで、初心者のAI活用はかなり変わります。

VOICE PROMPT BASICS

音声入力で話すことは、まず5つでいい。

初心者が止まりやすいのは「何を話せばいいかわからない」瞬間です。難しい長文プロンプトを覚えるより、今AIに何をしてほしいかをこの5つから選んで話す方が早いです。

01

情報収集

知らないこと、相場、選択肢、背景を集めたい時。「〇〇について短く教えて」「表で比較して」と話す。

02

理解

難しい言葉や仕組みをわかりたい時。「初心者向けに」「例え話で」「専門用語をかみ砕いて」と頼む。

03

評価・比較

どちらが良いか、何が弱いかを見たい時。「メリット・デメリットで」「改善点を出して」と聞く。

04

整形

出てきた内容を見やすくしたい時。「箇条書きで」「Markdownで」「台本形式で」と整える。

05

生成

文章、画像案、コード、資料を作りたい時。「〇〇向けに作って」「30秒で話せる文章にして」と頼む。

ズレた時の言い方

うまく言語化できなくても、「なんか違う。どこが違いそうか候補を出して」「もっと初心者向け」「短く」「比較表にして」と追加で話せば大丈夫です。音声入力は、最初の一発よりも、見て直すラリーで強くなります。

FIRST 7 STEPS

初心者が最初にやること

01

目的を話す

何を作るか、誰に使わせるか、なぜ必要かを音声で話す。

02

フォルダを渡す

関連ファイルが入ったフォルダをCodexのプロジェクトとして開く。

03

Plan Mode

いきなり作らせず、まず内容・方針・リスクを相談する。

04

実装を任せる

決まったら「実装して」と頼み、作業を進めてもらう。

05

差分を見る

何が変わったかを読み、意図とズレていないか確認する。

06

直す

違和感をまた音声で伝え、2周目、3周目で磨く。

07

学びを残す

決めたルールや失敗をAGENTS.mdやai-learningに保存する。

PRACTICAL EXAMPLES

Codexに任せる実例

LP修正

「このページを初心者向けにして。CTAを増やして、スマホで見やすくして」と頼む。

HTML資料作成

YouTubeや議事録を参考に、研修資料のHTMLを作らせる。

議事録整理

文字起こしをMarkdown化し、決定事項、TODO、次回論点に分ける。

画像付き資料

資料の流れを決め、必要な図や画像を生成してページに組み込む。

PC操作

Computer Useで画面を見ながら、GUIだけで起きる確認作業を手伝わせる。

既存コード調査

「この仕組みがどこにあるか調べて」と頼み、ファイル構成と修正方針を出させる。

DO NOT SKIP

初心者が避けるべきこと

秘密情報をそのまま渡さない

顧客情報、パスワード、APIキー、契約情報は扱いを分ける。必要なら伏せ字や別管理にする。

いきなり公開しない

Web公開はセキュリティリスクがある。初心者はまずローカルHTMLや社内資料から始める。

フルアクセスを常用しない

権限が強いほど便利だが、誤操作の影響も大きい。Sandboxと承認を基本にする。

AI任せで見ないまま納品しない

AIは作れるが、責任は人間に残る。成果物、リンク、文言、表示崩れは必ず確認する。
