概念の次は、実際に動かす

Codexを初心者でも安全に動かす操作マニュアル。

Plan Mode、プレビュー、権限、推論レベル、Skills、便利なフォルダ構成まで。AIエージェントに作業を任せるときの「どこを押すか」「何を選ぶか」「何を言うか」をまとめました。

OPERATION POLICY

操作方針

1

作業が未来感になる導線。 Codexをただの編集係ではなく、自分の仕事チームとして扱う。

2

選択を絞る。 初心者は標準権限、推論は中か高、まず小さな1作業から始める。

3

折れない設計。 失敗しても戻せる範囲で試し、確認しながら改善する。

4

文脈・権限・検証が核心。 目的を音声で渡し、Planで固め、Previewで見て、学びを残す。

BASIC FLOW

Codexは、この順番で使う。

最初から完璧な指示を出そうとしなくて大丈夫です。大事なのは、作る前に相談し、作った後に必ず見ることです。

01

プロジェクトを開く

作業したいフォルダをCodexのプロジェクトとして開く。関係ないフォルダまで広げすぎない。

02

目的を音声で渡す

誰向け、何を作る、制約、完成条件を口でまとめて話す。短文だけだとズレやすい。

03

Plan Modeで固める

いきなり実装させず、構成、リスク、テスト方法を先に出してもらう。

04

実装してもらう

計画に問題がなければ「この計画で実装して」と頼む。作業中も追加条件を伝えてよい。

05

Previewで見る

HTMLやアプリをブラウザで開き、PC幅とスマホ幅で見た目を確認する。

06

差分を見る

何を変えたか、不要な変更がないかを確認する。納品前の人間チェックは必須。

07

直しを頼む

違和感をそのまま話す。「もっと初心者向け」「色が強い」など感覚でもよい。

08

学びを残す

次も使うルールはAGENTS.mdやai-learningに保存する。ここからAIが育ちます。

VOICE PROMPT BASICS

音声入力は「5つの目的」から話す。

Codexに頼む時も、Claude Codeに頼む時も、最初に「何をしてほしいか」を選ぶと指示が安定します。音声で長く話す時は、この5つを見ながら話せば十分です。

01

情報収集

調べたい、選択肢を出したい、背景を知りたい時。

02

理解

難しい内容を、初心者向け・例え話・手順に変えたい時。

03

評価・比較

良し悪し、メリット・デメリット、改善点を見たい時。

04

整形

箇条書き、表、Markdown、台本など、見せ方を整えたい時。

05

生成

文章、HTML、コード、画像案、資料などを新しく作りたい時。

音声で話す型

今から〇〇について話します。目的は、情報収集／理解／評価・比較／整形／生成のうち〇〇です。対象者は〇〇で、完成形は〇〇です。まず足りない前提があれば聞いてから進めてください。

THREAD MODES

Local、Worktree、Cloudの選び方

モード 何をする場か 初心者の使いどころ 注意
Local 今のフォルダを直接編集する。 静的HTML、資料、ちょっとした修正。 直接変わるので、差分確認を必ずする。
Worktree Gitの別作業場で変更を分ける。 試したい案、複数案比較、大きめ修正。 Git管理されているプロジェクトで使いやすい。
Cloud リモート環境で作業する。 長めの作業、手元を軽くしたい作業。 環境設定や権限の理解が必要。最初はLocal中心でよい。

PLAN MODE

Plan Modeは、作る前の作戦会議。

初心者ほど、いきなり「作って」ではなく「まず計画して」と頼むのが大事です。完成条件を先にそろえると、後戻りが減ります。

使うべき時

新規ページ、複数ファイル修正、デザイン変更、公開前チェック、やり方に迷う作業。

使わなくてよい時

誤字修正、1文変更、リンク差し替えなど、失敗しても戻しやすい小さな作業。

確認すること

目的、対象者、完成条件、触るファイル、触らないファイル、確認方法。

合図の出し方

「まずPlan Modeで、実装せずに計画だけ出して」と明確に伝える。

そのまま使える依頼文

まずPlan Modeで相談してください。まだ実装はしないでください。目的は〇〇で、対象者は〇〇です。触ってよいファイルは〇〇、触ってほしくない場所は〇〇です。完成条件とリスク、確認方法まで含めて計画を出してください。

PREVIEW LOOP

Previewは、AI任せを人間の目に戻す場所。

見た目の良し悪し、文字のはみ出し、スマホ表示の違和感は、最後は画面で見ないとわかりません。

静的HTML

HTMLファイルだけで動く場合は、ローカルサーバーやブラウザで開いて確認します。

例: 資料ページ、LP、単一HTML

アプリ

ReactやFastAPIなどは、開発サーバーを立ち上げてURLを開きます。

例: localhost:3000、127.0.0.1:8000

自動Preview

利用できる場合はオンにして、Codexに「プレビューを見ながら直して」と頼みます。

表示崩れ、リンク、ボタン、スマホ幅を確認

見る順番

1. PC幅
最初の見た目と導線を見る。

2. スマホ幅
文字はみ出しと重なりを見る。

3. クリック
ページ遷移、外部リンク、戻る導線を見る。

4. 差分
余計な変更が混ざっていないか見る。

PERMISSIONS

権限は、便利さと危険さがセット。

初心者は標準権限を基本にします。Full accessは「何をしてよいか」がはっきりしていて、消えて困るものがない作業場でだけ使います。

権限 得意な場面 リスク 初心者判断
標準権限 現在の作業フォルダ内の編集、通常コマンド。 範囲外の操作は止まるので、少し待ちが出る。 最初はこれ。迷ったらこれ。
Auto-review 承認判断をある程度スムーズにしたい作業。 承認が自動寄りでも、作業範囲の理解は必要。 慣れてきたら使う。秘密情報や削除系は慎重に。
Full access 複数フォルダ横断、ネット利用、環境構築など止まりやすい作業。 フォルダ外の変更、削除、移動、秘密情報への接触が起きやすい。 常用しない。空の検証フォルダやバックアップ済み作業だけ。

Full accessが得意なこと

開発サーバー起動、依存関係インストール、複数フォルダ参照、外部データ取得など、標準権限で何度も止まる作業。

Full accessで避けること

デスクトップ全体、OneDrive全体、秘密情報入りフォルダ、顧客情報、バックアップなしの削除や移動。

REASONING LEVEL

推論レベルは「高ければ常に正解」ではない。

考える量が増えるほど、重い作業に向きます。ただし軽い修正まで非常に高いにすると、遅くなったり、考えすぎたりします。

中

軽い修正・資料整理

文言変更、HTMLの小修正、議事録整理、既存デザインに合わせる作業。

高

標準の本命

複数ファイル、設計判断、原因調査、PC/スマホ表示確認、教材構成のような作業。

非常に高い

難しい時だけ

原因不明のバグ、大規模コード理解、複雑な仕様整理、長い作業計画、失敗コストが大きい判断。

初心者の初期値

迷ったら「高」。軽い作業なら「中」。何度やってもズレる、ファイル数が多い、前提が複雑なら「非常に高い」。この3択で十分です。

SKILLS

Skillsは、毎回の説明を減らす仕組み。

Skillsは「この作業はこの手順でやる」「このデザイン型を使う」という再利用ルールです。CodexでもClaude Codeでも、強い人は毎回ゼロから説明しません。

使う場面

同じ形式の資料、同じデザイン、同じ検証手順、同じ会社ルールを何度も使う時。

初心者の頼み方

「このページはroot1039-pageの型に合わせて」「この作業をSkill化できるか見て」と頼む。

Claude Codeにも効く考え方

Skillsの有無に関わらず、作業ルールをMarkdownにして常に読ませると精度が上がる。

安全確認

知らないSkillや外部から取った手順は、中身を読んで危ない操作がないか確認してから使う。

CONTEXT FOLDERS

持っておくと便利なファイル・フォルダ

AIエージェントは、文脈が多いほど判断が安定します。フォルダ構成を整えることは、AIに仕事を教えることです。

AGENTS.md

作業ルール、触ってよい範囲、文章トーン、検証方法を書く。

ai-learning/

学び、失敗、再利用パターンを残す。CodexとClaude Codeの共有記憶になる。

docs/ または context/

仕様、背景、議事録、判断理由など、AIに読ませる資料置き場。

assets/

画像、ロゴ、スクリーンショット、参考デザインを置く。

examples/

過去に良かったページ、資料、プロンプト例を置く。

outputs/

生成物や一時成果物を置く。後で確認しやすくする。

作らない方がよい置き場

`secrets/`、APIキー置き場、パスワードメモ、顧客個人情報の丸ごと保管は避けます。必要な秘密情報は、AIに見せる資料とは分けて管理します。

PROMPT TEMPLATES

実例別、そのまま使える依頼文

LP修正

このHTMLを初心者向けのLPとして見直してください。まずPlan Modeで、構成・CTA・スマホ表示・変更するファイル・確認方法を出してください。実装はまだしないでください。

HTML資料作成

このフォルダ内の資料を参考に、初心者向けの説明ページを新規HTMLで作ってください。専門用語はかみ砕き、操作手順と注意点を入れてください。完成後はプレビューで確認してください。

既存コード調査

まだ修正しないでください。この機能がどのファイルで動いているか調べ、関係ファイル、データの流れ、直すならどこを触るかを説明してください。

画像付きページ

このページに合う画像や図の案を出し、必要なら生成・配置してください。暗すぎる画像や内容がわからない装飾画像は避け、実際に伝えたい内容が見えるようにしてください。

議事録整理

この議事録を、決定事項、TODO、未決事項、次回確認、背景メモに分けてMarkdownにしてください。曖昧な箇所は勝手に断定せず、確認が必要として残してください。

PC操作依頼

画面を見ながら操作してほしいです。実行前に、何をクリックするか、どの情報を入力するか、外部に送信する情報があるかを説明してください。危ない操作は止まって確認してください。
